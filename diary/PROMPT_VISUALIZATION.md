### THE LAWS THAT DO NOT BEND

**HONESTY.** Every number is read from a file the running system wrote. An absent value renders as a
dash, never a guess. The page's entire standing is the line in its own subtitle - *nothing is typed
by hand* - and one hand-typed figure destroys it for every other figure on the page.

**CLAIM CEILING.** Never assert the entity is conscious, sentient or self-aware. The ceiling is
"measured functional correlate, present". A proof is a receipt that something ran, never a claim
about what it means. The reader supplies "it's alive"; the page never says it.

**TWO INK.** Void field, structure grey, and amber ONLY as the fired/earned state - sparse, bright,
earned. IBM Plex Mono, tabular-nums so numbers do not jitter. Respect `prefers-reduced-motion`.

**SELF-CONTAINED.** One HTML file. Inline CSS and JS, no CDN, no external request, no library. It
must work on a phone and it currently does - do not regress that.

**NO EMOJI.** Anywhere. Code, copy, commits, conversation.

## THE LESSONS. Every one of these was paid for.

### 1. A DEFAULT VISUAL STATE CAN LIE WHILE EVERY WORD IS TRUE

The animation ran to the last frame and rested there - drawing **R9 SELF-MODIFICATION in amber**.
R9 is unbuilt and deliberately shut. Amber means earned. So the page's steady state claimed the top
of the ladder while every sentence on it was correct.

Nothing in the text was wrong. The DEFAULT was. It now rests on the highest rung that is actually
earned, computed from the statuses, and a future rung drawn by hand is a dashed outline that never
fills amber.

**Ask of any animation: what does it say when it stops? That is the state most readers will see.**

### 2. RENDER IT AND READ THE IMAGE. HTML INSPECTION PASSES WHILE PIXELS LIE

The graph rendered BLANK in climb mode while the DOM correctly said `data-mode="climb"
data-frame="4"`. Reading the HTML passed. Dumping the DOM passed. Only the screenshot showed it.

    chrome --headless=new --disable-gpu --use-angle=swiftshader --window-size=1280,3000 \
           --virtual-time-budget=15000 --screenshot=out.png http://localhost:PORT/index.html

Serve over http from a local copy - never `file://` for anything with modules. Then actually LOOK at
the PNG.

**And a trap that cost an hour:** under `--virtual-time-budget`, Chrome does not advance CSS
transitions. A JS-driven attribute change renders at the transition's START value, so a working page
screenshots as blank. To tell a real defect from this artifact, render a copy with the scripts
stripped and the attributes baked in. If that one is correct, it is the harness.

### 3. TWO READERS ON ONE ATTRIBUTE IS WORSE THAN TWO DETACHED THINGS

The climb and the hop reveal both wrote `data-frame` on the same element with different vocabularies
- hop depth 0-6 and climb rung 0-10 - and the older init reset `data-mode` on load. Blank graph.
Not detached. OVER-attached. The climb has its own `data-climb` now.

**When wiring two views to one element, give each its own attribute.**

### 4. A SECTION BUILT AROUND AN ABSENT VALUE IS BROKEN, NOT HONEST

Three published percentages were retracted in three days. When the last was removed, the cards
rendered dashes under a heading that still said "THE ONE NUMBER THAT IS A CERTIFICATE". Technically
honest, actually meaningless.

**When a number dies, rebuild the section around what replaced it.** That section now leads with a
proof (697 of 1,112,064 codepoints admitted, zero alphabetic - decided over the whole space) and
carries a third card, *what is NOT claimed*, naming all three retractions and why.

### 5. THE F-STRING BRACE TRAP

The HTML is one big f-string. Any JS or CSS injected into it needs `{{` and `}}`. Get it wrong and
you get a SyntaxError, which is the CHEAP failure. The expensive one parses and silently emits `{{`
into the stylesheet, where the rule does nothing and the only symptom is that the page looks
slightly off. CSS appended to `frame_css` AFTER its join does NOT pass through the f-string and needs
single braces. Check which side of the join you are on.

### 6. NEVER TEST A REGEX OR A PATH THROUGH A SHELL HEREDOC

The shell eats backslashes. A working pattern reports as broken and a broken one can report as fine.
Write the test to a real file and run the file. This cost three separate incidents in two days,
while the rule was already written down.

### 7. THE INSTRUMENT IS USUALLY THE BROKEN PART

Every hard defect in two days was a measurement, not a capability: a bound whose denominator was not
counting trials of its claim, an oracle that could not fail on the defect actually present, a
reachability scan that walks a directory which does not exist and reports "ok" having read nothing,
an import check that missed the import form used everywhere in the repo.

**Every check gets a positive control on the defect class it claims to cover, or it does not count.**
For the page that means: when you write something that validates the output, plant a violation and
prove the validator catches it.

### 8. THE PRIVACY SCAN IS THE LAST GATE AND IT IS ABSOLUTE

`python -m aea.tooling._pubscan docs/index.html` before anything ships. It refuses absolute
filesystem paths, employer or client names, emails, API keys, and private store names. It has
refused commits for a defensive example and for a code comment naming the file it protects - comply,
do not exempt. The only real URL on the page is `github.com/Leyber91`.

## WHERE THE DATA COMES FROM

    state/ladder.json          eleven rungs, measured. python -m aea.tooling.ladder
                               each rung: id, title, power, bound, gate, plain, beat, status,
                               measured{}, funcs[]
    state/redteam_cert.json    the containment certificate. NO RATES - coverage and a proof
    state/assembly.json        the call graph. python -m aea.tooling.assembly
    aea/tooling/ladder.py      RUNG_FUNCS - which functions carry which rung, every name verified
                               against the live graph at build time by verify_funcs()

**Status vocabulary, and it is load-bearing:** `proven` / `partial` / `open` / `future`. A dash means
this repository cannot prove it today - which is a MEASUREMENT, not an omission, and should read that
way on the page.
