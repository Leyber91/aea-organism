The filter & the two hard trades

decided, not asked
KEEP — working piece, untouched, designed around PORT — real logic carried into a clean module NEW — designed + written fresh CUT — retired to dev/ or deleted

The engineering standard is right, and the current code is flat/monolithic/forked in two places. But the verification pass proved the substrate is not the mess: aea/ is stdlib-only, cleanly layered (grid = root, zero cycles), single-responsibility, and every module is under your 500-line ceiling except two — controlroom.py (689) and world.html (78KB). Those two are the seam-host and the client, which we rebuild regardless. So "from scratch" earns its keep on the seam + client + config-as-data; the live entity is careful surgery, PORT/KEEP.

Trade 1 · the entity — RECOMMENDATION
KEEP-AND-WRAP the substrate. Do NOT reorganize the live entity into new OOP classes.
Why: (a) its state is live — a missed write-site silently splits/resets state (D8), and 34 modules to rewrite multiplies that for zero player-visible gain; (b) it's already well-factored (the import graph is clean and layered, single-responsibility, under the size cap); (c) the moat is the REAL behavior — wrapping it preserves the moat with minimal risk. The one substrate monolith, controlroom.py, is dissolved by the rebuild (its game logic PORTs into the seam package). grid.py (479 loc, 5 responsibilities) earns a later careful split into a grid/ package, but that is off the first-light path and touches every import site — deferred, not now.
Trade 2 · the client module system — RECOMMENDATION
Native ES modules (import/export), no build step. Retire the window.GAME global + IIFE pattern.
Why: real encapsulation and explicit dependency edges beat a shared global with implicit ordering. No build cost — browsers load ESM over http natively. THREE r128 (UMD) stays a classic global <script> loaded first; the bloom chain attaches to it; the game code is proper modules behind one <script type="module" src="core/main.js">. Consequence: the 5 clean IIFE modules (engine/bench/panels/seals/artifacts) become PORT (convert to ESM classes), not KEEP — but that is the client rebuild we already committed to. The single global is replaced by explicit imports + one injected Game context object passed to each module's constructor.
01

The architecture — three layers, one firewall

dependencies point inward only

Strict inward dependency: client → seam → substrate. The substrate imports nothing outward. The seam is the only thing that knows about both sides. The honesty law + claim ceiling live in exactly ONE place — the firewall class in the seam. Nothing crosses the wire except through it.

SUBSTRATE — aea/
KEEP-AND-WRAP · the moat · imports nothing outward
The real always-on entity: the only place a token burns or a number is measured. 34 stdlib modules, layered (grid root → energy/trust/pulse → bench_core/hades/talk). Reorganized only by careful surgery; otherwise untouched.
SEAM — aea/gameapi/
NEW · the only two-sided module · the firewall
A small package (not a 689-line file): a thin HTTP router + the honesty firewall class + read/act handlers that call the preserved organs + the shared /game/* contract. Dissolves controlroom.py. Every reply is HTTP 200 + JSON.
CLIENT — web/ (ES modules)
REBUILT · presentation + play only · owns zero truth
Native ES modules grouped by domain (core/world/compose/catalogue/hud/missions/audio). One api.js talks to the seam; one client EventBus makes the run legible; modules receive an injected Game context, never a global.
web/  —import→  api.js  —fetch /game/*→  gameapi/honesty.py  —calls→  aea/ organs  ·  truth returns outward, curated, or as a dash

Dependencies — inward only, no cycles

verified from source

Runtime

  • Python: stdlib-only (confirmed — no requirements.txt/pyproject; HTTP via http.server/urllib). The only third-party imports in aea/ are 4 guarded voice deps (sherpa_onnx, edge_tts, sounddevice) — none on the game path. The seam adds none.
  • Client: three.js r128 (UMD) + the 6-file bloom chain, no build step. THREE loads as a classic global script; the game is native ES modules over http. No npm, no transpile.
  • .env: 13 provider keys (all gitignored). First light needs none — it is guarded on the keyless local hearth (ollama).

The client↔server contract & the firewall

one boundary, one class

The /game/* shapes are declared once in gameapi/contract.py and checked from both sides. Every reply is HTTP 200 + JSON; errors and refusals ride in the body. The firewall is the sole enforcement point.

/game/*kindcalls the REAL organfirewall rule
/game/stateGET readcontrolroom.state (PORT)absent field → null → dash; tokens None at P0 → dash, never 0
/game/catalogueGET readroster (PORT)un-met model → shadow, not a fake stat
/game/events?since=GET readpulse.tailempty → quiet, never invented
/game/schemaGET reada real fog source NEWtoday's schema.json is a stale code graph — needs a game fog map (Issues)
/game/ignite {spec}POST actbench_core.start_run2nd-while-live → refused; bad spec → refused:'<clause>'; one run at a time
/game/run?id=GET readbench_core.run_statushalted = visible blue fail; pass through as-is
/game/fire {node}POST actenergy.draw (the only token burn)empty text from a live rod = failure (dash), never fabricate
/game/talk · /game/savePOST acttalk.answer · _journey writerzone-routed; save merged under grid.file_lock, SACRED
gameapi/honesty.py — the firewall class (NEW) One class wraps every handler: it catches organ exceptions and returns a receipt (never a 5xx), maps None/missing to a dash sentinel the client renders as an em-dash, formats refusals as {ok:false, refused:'<clause>'}, and enforces the claim ceiling on any generated copy. It is the only code allowed to shape a /game/* body. The contract test asserts no handler bypasses it.
