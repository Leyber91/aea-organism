## 1. PREAMBLE — what is being produced

THE PROBE is a game never seen before, built to become a popular-culture reference for
understanding AI. It does not mystify the machine — it makes MAGIC OUT OF THE REAL:
every number on screen is live system truth, every construct the player composes
actually runs, and no claim ever rises above "measured functional correlate"
(canon: Luis, 2026-07-20). The core creative act is composing AEA combinations into
REAL running constructs; each player's collection of assistants is their character —
the thing they build, prove, and show. Play is open-ended inside each rung of the
assistant ladder and gated between rungs (chat → sources → memory → flows → powers →
the wild). The whole game is a learning reference on AI: a player who can predict the
entity can build one. This page is the manual's index — the twelve processes that make
that game, the stories each serves, the specs that govern them, the graphical data
owed, and every open ticket in one registry.

## 4. HOW TO USE THE MANUAL — the work session loop

1. **Pick the slice.** Open P0_PROTOTYPES.md and pick the prototype for this session
   (if that page is not yet on disk, 09_PRODUCTION §3's build queue is the order —
   nothing enters ahead of it without displacing something by name).
2. **Open its tickets.** Find the prototype's process in §2, pull its ticket ids from
   §3. Check every gate: a [DECISION-LUIS] ticket is specced, not built, until the
   ledger number clears (BOOK.md, THE OPEN DECISIONS LEDGER).
3. **Open its specs.** Each ticket's source column names the exact chapter section.
   Read it before building — the chapter governs; this index only points.
4. **Build.** FIELD work is a solo execution session; anything touching entity code is
   a FORGE pair session under A9's five phases (Luis judge+hand, Claude smith, HADES
   gate). The game never pretends the UI wrote the code.
5. **Verify.** Per 04 §7's harness (?still, ?os=<tab>) and 08_TECH's recipes; anything
   touching emissive/bloom/tone-mapping verifies on BOTH pipelines (risk R2). A change
   is done when it ran and was seen — never when it compiles in your head.
6. **Log.** 09_PRODUCTION updates in the same commit as the thing it records — shipped
   slice to §1, playtest to §2, queue movement to §3. A slice without a §1 entry did
   not ship. Chapter edits carry dated lines; decisions land in the BOOK ledger; a
   closed ticket is FLIPPED IN tickets.json with its evidence named (E3_TRACKING §3's
   commit-equivalent is the primary act — §3 here is a frozen transcript and is not
   re-struck). — edited 2026-07-20 (nine-critic closure)

One phase at a time. Re-planning is legitimate only against new evidence — a shipped
artifact, playtest data, or a Luis decision. When tempted to re-plan, execute the
current prototype's next ticket instead.
