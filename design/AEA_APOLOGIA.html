The combination space

the laws that gate it — REAL; the space they govern — not yet built
  • Composition primitive (one engine): a construct is a POINTER SET of part-ids into modules.json + tier requests + wiring + ONE zone. Running RE-WALKS the wiring and fires each part's REAL organ entry point. There is no second execution engine — the bench is a harness over the same organs that run the entity.
  • The hard gate (what composes today): validate_spec legalizes a part only if registered + bench_part + status BUILT + present on disk + in FIREABLE. That intersection is exactly 5. 11 more carry bench_part but are refused BY NAME (BUILT "no P0 fire path" / FORGE-PENDING / INGREDIENT "proven in isolation, not wired").
  • Rail law: TAP holds parts[0]; SCORER holds the tail; one seat per part. Seating LADDER is THE REACH — lifts the run to a cloud tier and spends real budget.
  • Zone arithmetic (the core viability law): zone(A∘B) = STRICTER(zone A, zone B) — strictness sensitive>private>public; combination NEVER loosens. One private part correctly poisons the whole construct toward local. Four rings: LOCAL > NO-TRAIN > TRAINS > KEYLESS. A correctly-held strict route is a SCORING EVENT (warm amber), never a red refusal.
  • The gate law: HADES + trust + meter + pulse + tracelog WRAP every construct and can NEVER be a part inside one — the bracket frame. send_outbound/spend_money/manage_keys stay FORBIDDEN at charter level 0 over ANY spec. Only the player's control surfaces unlock; the entity's governance never does.
  • Energy continuum law: NO part ever names a model. A part requests a TIER (reflex/bulk/deep) and energy.ladder resolves tier→rod at draw time from the live census + fitness + meter, falling to the local floor so the heartbeat never stops. Autonomy lives in the structure, not the weights.
  • The join table (8 port classes): POWER · PROMPT · GROUNDING · SCORE · CONSTRAINT · EXTERNAL · SPEECH · ARTIFACT. Class must match; EXTERNAL may only meet the MEMBRANE; ARTIFACT is terminal. [derived / planned]
  • Pool climbs by rung 5→7→12→14→17 (Slay-the-Spire registered / unlocked / slotted discipline — three files, never merged).
  • R30 / D9 viability doctrine (the teaching): the composer GENERATES entities and MOST are NON-VIABLE — that IS the point. Viable iff it actually runs on real models/tools/rate-limits. Failure signatures mirror real agent-arch failures: senses-but-no-hands (observes, can't act) · loop-no-memory (never integrates) · brain-too-slow (starves the rate window) · no-governor (runaway cost). Viability is a spectrum, not binary.
